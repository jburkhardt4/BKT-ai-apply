### 1. Pin Playwright to `1.62.1` — 1.62.0 has a *fatal* regression on THIS repo's tsconfig  [S111]
**[Recommend: IMPLEMENT]** (queued pending GitHub + approval)  ·  Theme 1 · release safety · **supersedes S106**

- **What's new:** Playwright **1.62.1** shipped **Jul 30 2026** (current stable). It fixes two regressions that
  were **fatal since 1.62.0**: (a) directory/path-form tsconfig **project references** (`{ "path": "../pkg" }`)
  failing to resolve, and (b) tsconfig `"extends"` bare specifiers not resolving via the `node_modules` walk-up
  the way `tsc` does — plus an accessibility-snapshot fix (see S112).
- **Why it matters for bk-ai-apply:** the repo's **`tsconfig.json` is a solution-style file** —
  `"references": [{ "path": "./tsconfig.app.json" }, { "path": "./tsconfig.node.json" }]` — i.e. exactly the
  path-form project-reference construct that **1.62.0 breaks**. Had S106 landed as `1.62.0`, `playwright test`
  could fail to resolve the project's TypeScript config on load. **1.62.1 is the correct pin target** and the
  literal answer to S106's "check for a 1.62.x patch first." Do **one** bump to **1.62.1**, not 1.62.0.
- **Concrete change (narrow):** in `package.json` set `"@playwright/test": "1.62.1"` and `"playwright": "1.62.1"`
  (drop the `^` to keep the exact-pin discipline), then `pnpm install` and `pnpm exec playwright install
  --with-deps`. Validate with `pnpm validate` **plus** all three configs (`playwright.config.ts`,
  `playwright.uat.config.ts`, `playwright.extension.config.ts`) and a `pnpm test:uat:smoke` run.
  **Rollback:** revert the two version lines + `pnpm install`.
- **Source:** microsoft/playwright — *Release v1.62.1*, **Jul 30 2026** (regression fixes for tsconfig
  `extends`/project-references). Version/date cross-checked against the npm registry (`dist-tags.latest = 1.62.1`,
  published 2026-07-30).
- **Recommended action:** **IMPLEMENT** — genuine gap (repo is two minors back **and** the naive 1.62.0 target
  would break this repo's tsconfig); apply as a narrow dep-bump PR on a branch off `ai/daily-suggestions` once
  GitHub is connected. Never `main`, always a DRAFT PR.

### 2. 1.62.1 aria-snapshot fix restores button names hidden behind icon SVGs — sharper AI-UAT a11y snapshots  [S112]
**[Recommend: TRACK]**  ·  Theme 1 (visual/a11y validation) · rides **S111** · improves **S19 / S58**

- **What's new:** Playwright **1.62.1** fixes an accessibility-snapshot bug where a control's **accessible name
  was dropped** when its visible text sits inside `<span>`s alongside an `aria-hidden` **SVG icon**. After the
  fix, `ariaSnapshot()` / `toMatchAriaSnapshot()` capture the button's real name again.
- **Why it matters for bk-ai-apply:** the pipeline board, doc-builder, and prospector screens are full of
  **icon + text buttons** (Lucide/Radix patterns wrap the label in a `<span>` next to an `aria-hidden` SVG) —
  precisely the shape that triggered the 1.62.0 bug. On 1.60.0/1.62.0 an AI-UAT ARIA snapshot (S19) or the
  boxed a11y tree (S58) would render those buttons **nameless**, producing noisy, low-value goldens the
  `@explorer` specs can't assert against. 1.62.1 makes the a11y snapshots trustworthy again.
- **Concrete change (with S111, no standalone code):** land it as part of the S111 bump; when S19's
  `toMatchAriaSnapshot` gate is authored, expect button names to appear in the tree — assert on them (e.g.
  `- button "Move to Interview"`), and re-baseline any pre-1.62.1 ARIA goldens.
- **Source:** microsoft/playwright — *Release v1.62.1* ("accessibility snapshot drops button name when text is
  nested inside spans with aria-hidden SVG"), **Jul 30 2026**.
- **Recommended action:** **TRACK** — a fidelity fix that rides the S111 bump and makes the still-open S19/S58
  a11y-snapshot cards worth adopting; nothing to implement standalone.
