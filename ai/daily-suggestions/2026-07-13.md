### S58 — Playwright `ariaSnapshot({ boxes: true })` gives the AI-UAT agent element coordinates without vision inference  ·  [Recommend: TRACK]

- **What's new:** Playwright **1.60** (May 2026) added a `boxes` option to `locator.ariaSnapshot()` / `page.ariaSnapshot()`. When `true`, each element in the accessibility-tree snapshot is annotated with its bounding box `[box=x,y,width,height]` (viewport CSS px, from `getBoundingClientRect()`) — Playwright documents this as being "for AI consumption."
- **Why it matters for bk-ai-apply:** the AI-UAT suite drives a browser through Stagehand + Browserbase (`e2e/ai-uat/`, `ANTHROPIC_KEY` + `BROWSERBASE_*` in `ai-uat.yml`). A box-annotated ARIA snapshot lets the agent know both *what* an element is and *where* it sits — so it can target actions from semantics + layout **without** taking a screenshot and paying for vision inference on every step. That means cheaper Browserbase/token spend and less positional flakiness. The repo is **already on `1.60.0`**, so this needs no version bump (unlike S36/S53).
- **Concrete change (narrow):** in the harness where page state is serialized for the agent (`e2e/ai-uat/_helpers/setup.ts`), capture `await page.ariaSnapshot({ boxes: true })` and pass it as the agent's observation context; A/B the Browserbase/vision spend on `smoke.spec.ts` before wiring it into the other scenarios. No CI change.
- **Source(s):** Playwright v1.60 release notes + Locator API docs — playwright.dev/docs/release-notes, playwright.dev/docs/api/class-locator; github.com/microsoft/playwright/releases/tag/v1.60.0 (May 2026).
- **Recommend:** **TRACK** — additive AI-perception enhancement; validate token/flake impact first. Distinct from S19 (ARIA-snapshot *assertions*) and S21 (Chrome DevTools MCP).
