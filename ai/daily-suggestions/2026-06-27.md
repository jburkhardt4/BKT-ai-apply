### S35 — Wire Vercel **Protection Bypass for Automation** so AI-UAT can run against protected **preview** deployments
- **What's new:** Vercel's **Protection Bypass for Automation** issues a per-project secret
  that automated clients send as the `x-vercel-protection-bypass` HTTP header (optionally
  with `x-vercel-set-bypass-cookie: true`) to reach **Deployment-Protection-protected**
  URLs without hitting the auth challenge. Vercel auto-exposes it as the
  `VERCEL_AUTOMATION_BYPASS_SECRET` system env var, supports multiple revocable secrets per
  project, and its 2026 "Automated & Agent Access" docs formalize the pattern for CI and
  agents. Playwright reads it via `use.extraHTTPHeaders`.
- **Why it matters for bk-ai-apply:** AI-UAT today resolves `AI_UAT_BASE_URL` to **prod**
  Vercel or a **Codespace** dev URL, and `playwright.uat.config.ts` sets **no bypass
  header**. Preview deployments are protected by default — so the S03 plan (auto-trigger
  AI-UAT on `deployment_status` preview success) **cannot actually load a protected
  preview**: the Stagehand agent would land on Vercel's auth wall, not the app. This is the
  missing primitive that makes per-PR preview UAT real, and it's the *safe* path (a scoped,
  revocable secret) rather than turning Deployment Protection off.
- **Concrete change (narrow):** in `playwright.uat.config.ts`, add — only when the env var
  is set, so local/Codespace runs are unaffected —
  `use.extraHTTPHeaders = process.env.VERCEL_AUTOMATION_BYPASS_SECRET ? { 'x-vercel-protection-bypass': process.env.VERCEL_AUTOMATION_BYPASS_SECRET, 'x-vercel-set-bypass-cookie': 'true' } : undefined`.
  Add `VERCEL_AUTOMATION_BYPASS_SECRET: ${{ secrets.VERCEL_AUTOMATION_BYPASS_SECRET }}` to
  the `ai-uat.yml` env. **JB provisions the secret** (Vercel → Project → Settings →
  Deployment Protection → Protection Bypass for Automation) and adds the repo secret — the
  routine does **not** create or modify secrets.
- **Sources:** [Protection Bypass for Automation — Vercel Docs](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/protection-bypass-automation);
  [Automated & Agent Access — Vercel Docs](https://vercel.com/docs/deployment-protection/automated-agent-access) (2026).
- **Recommended action: IMPLEMENT** — small, guarded config change that unblocks the
  tracked S03 preview-UAT trigger; reversible; the only external dependency is a JB-owned
  Vercel secret.

### S36 — Adopt Playwright's 1.59–1.61 **agentic** APIs: Screencast recording + `locator.normalize()`
- **What's new:** the Playwright **1.59** ("agentic release," Apr 2026) → **1.61** (current
  stable; **1.60.0** shipped **May 11 2026**) line added a **Screencast API**
  (`screencast.start/stop`, action annotations that highlight interacted elements,
  chapter/HTML overlays, and **AI-optimized accessibility snapshots**) for programmatic,
  narratable recordings; **`locator.normalize()`**, which rewrites a locator toward
  best-practice **test-id / ARIA-role** selectors; plus `page.pickLocator()` and
  `page.routeWebSocket()`.
- **Why it matters for bk-ai-apply:** AI-UAT failure evidence today is `video:
  retain-on-failure` + `trace` — opaque to triage and to an autonomous loop. The Screencast
  API yields **narrated, action-annotated** recordings with a11y snapshots, far better
  evidence for both the loop and JB's review. And `locator.normalize()` directly hardens the
  **brittle, LLM-generated selectors Stagehand emits** — converting a flaky agent action
  into a stable, replayable assertion. The repo is pinned to `@playwright/test: 1.60.0`, so
  this is *adopt-the-new-APIs* (and a small 1.60→1.61 bump), distinct from the agents/ARIA
  (S12/S19) and MCP (S25) items already tracked.
- **Concrete change:** TRACK a spike on a branch — bump `@playwright/test` + `playwright`
  1.60 → 1.61; in `e2e/ai-uat/_helpers/setup.ts`, pass Stagehand-discovered targets through
  `locator.normalize()` before asserting; trial the Screencast API in
  `playwright.uat.config.ts` for one scenario and compare artifact quality vs. the current
  video/trace. Keep `retries: 0` (AI nondeterminism) and `workers: 1`.
- **Sources:** [Release notes — Playwright](https://playwright.dev/docs/release-notes);
  [What's new in Playwright 1.59 (Bug0)](https://bug0.com/blog/whats-new-playwright-1-59) (2026);
  [Playwright 1.60.0 Release Updates (currents.dev)](https://currents.dev/posts/pw-1.60.0) (May 2026).
- **Recommended action: TRACK** — version bump + API-adoption spike; validate artifact and

- **What's new:** Supabase's local-dev workflow supports a version-controlled

- **Why it matters for bk-ai-apply:** the repo ships **34 migrations** and a `config.toml`

  **no deterministic fixtures**: no known jobs/applications spanning the pipeline, nothing for
  the board to render reproducibly. Missing/variable data is the **#1 cause of flaky
  autonomous UAT**, so a checked-in seed is the deterministic-data foundation under Theme 1 —
  and the natural complement to S13 (Branching) and S26 (declarative schemas).
- **Concrete change:** add `supabase/seed.sql` with a **minimal, idempotent smoke fixture**
  — 2–3 companies/jobs and a handful of `applications` + `application_events` spanning
  Discovery→Offer — keyed to a documented `:test_user_id` (bound to the existing
  `TEST_USER_EMAIL` account, **not** an invented credential); register it via
  `[db.seed] sql_paths = ['./seed.sql']` in `config.toml`, splitting into `seeds/*.sql` as it
  grows. Preserve RLS + `user_id` scoping (non-negotiables #1/#5). Point
  `e2e/ai-uat/_helpers/setup.ts` at the seeded rows.
- **Sources:** [Seeding your database — Supabase Docs](https://supabase.com/docs/guides/local-development/seeding-your-database);

### S38 — Evaluate Claude Code **Agent Teams** for the `/dispatch` wave orchestration
- **What's new:** Claude Code **Agent Teams** (experimental, shipped **Feb 2026** with Opus
  4.6): set `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` (shell or `settings.json`) and each
  session gets an implicit team — **spawn teammates by name with no setup step**; each runs in
  its **own context window** and they coordinate **peer-to-peer via a mailbox + shared task
  list**, and you can address a teammate **directly**, not only through the lead. That's a
  different primitive from subagents, which run inside one session and only report back to the
  parent.
- **Why it matters for bk-ai-apply:** the repo's orchestration is a **hierarchical**
  Orchestrator → 12-subagent model (wave dispatch graphs, `agent-memory/orchestrator/`) — the
  classic one-parent/report-back shape that S22 (parallel fan-out + checkpoint/rewind) and S07
  (Dynamic Workflows) already push on. Agent Teams maps onto a multi-wave `/dispatch` where
  **Feature-Dev → Qa-Uat → Supabase-Security** must hand artifacts to each other **without
  round-tripping the Orchestrator**, and the shared task list / mailbox could relieve the
  Orchestrator-compaction pressure tracked in S27. Worth a scoped eval before `/dispatch`
  semantics are committed (still unbuilt per S06).
- **Concrete change:** TRACK a spike — enable `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` in a
  throwaway Codespace session; re-run one small slice (Feature-Dev → Qa-Uat → Release-Gate) as
  a **team** vs. the current subagent dispatch; compare context usage, hand-off fidelity, and
  compaction pressure; record the verdict in `docs/adr/` **before** changing `/dispatch`. No
  production wiring until evaluated.
- **Sources:** [Agent teams — Claude Code Docs](https://code.claude.com/docs/en/agent-teams);
  [Building a C compiler with a team of parallel Claudes — Anthropic Engineering](https://www.anthropic.com/engineering/building-c-compiler) (2026).

### S39 — Treat **AGENTS.md** as the cross-tool standard and wire a single source of truth
- **What's new:** **AGENTS.md** is now the cross-tool agent-instructions standard — originated
  by OpenAI, **stewarded by the Linux Foundation's Agentic AI Foundation**, and read natively
  by **28+ tools** (Codex CLI, Copilot, Cursor, Windsurf, Amp, Devin, Aider, Zed, VS Code,
  JetBrains Junie…) across **60k+ repos** as of mid-2026. **Claude Code now reads AGENTS.md
  too**, with CLAUDE.md as its richer native format. The recommended pattern is one source of
  truth plus a thin `CLAUDE.md` that pulls it in via an `@AGENTS.md` import (or a symlink) —
  not duplicated rules.
- **Why it matters for bk-ai-apply:** the repo has **both** a root `CLAUDE.md` (the real
  entry point — stack, non-negotiables, validation) **and** a root `AGENTS.md` — but the
  repo's `AGENTS.md` is an **agent *roster*** (wave status, entry points, engine-room agents),
  **not** the standard's build/test/convention instructions. Any external tool that now reads
  AGENTS.md natively will load the **roster** and **miss the actual conventions** in CLAUDE.md
  — the inverse of the standard's intent, and a divergence risk the moment the project is
  touched by Codex/Cursor/Copilot alongside Claude Code. Aligning extends S08's
  context-precision goal to the multi-tool world.
- **Concrete change:** decide in an ADR, then execute one of: **(a)** rename the roster to
  `docs/agent-roster.md`, make root `AGENTS.md` the canonical conventions file, and reduce
  `CLAUDE.md` to `@AGENTS.md` + Claude-specific overrides; or **(b)** keep `CLAUDE.md`
  canonical and add a standard-shaped `AGENTS.md` (setup / build / `pnpm validate` / conventions)
  that imports or links it. Either way: **one** source of truth, no duplicated rules, no two
  files drifting.
- **Sources:** [AGENTS.md spec & Agentic AI Foundation guide (morphllm.com)](https://www.morphllm.com/agents-md-guide) (2026);
  [Agent Instruction Files — Cross-Tool Portability with Codex CLI](https://codex.danielvaughan.com/2026/05/27/agent-instruction-files-agents-md-claude-md-cross-tool-portability-codex-cli/) (2026-05-27).
- **Recommended action: TRACK** — an ADR-worthy naming/sourcing decision with a real
  collision (their `AGENTS.md` ≠ the standard's); not a clean automated edit.
