## Suggestion Cards

### 1. `@supabase-labs/tanstack-db` (alpha) — a typed, live-query + optimistic-mutation data layer that auto-syncs the pipeline board over Realtime — [Recommend: TRACK]

- **What's new:** Supabase launched **`@supabase-labs/tanstack-db`** (alpha), a TanStack DB collection
  adapter backed by Supabase. It gives **live queries** (components re-render on data change, no manual
  cache invalidation), **optimistic mutations** (insert/update/delete apply instantly, auto-rollback if the
  server rejects), **automatic Realtime sync** (other clients' row changes propagate with no subscription
  code), and **end-to-end types derived from your schema**. It's a client-side data layer that plugs into an
  existing app with **no migration required**; it does **not** yet support SSR (collections fetch on the
  client). Announced in the **Supabase Developer Update — July 2026 (Jul 9 2026)** and the Supabase launch
  post. Install: `npm i @supabase-labs/tanstack-db @tanstack/react-db @supabase/supabase-js`.
- **Why it matters for bk-ai-apply:** The app is **React 19 + `supabase-js ^2.107` + Realtime** with a
  stage-based pipeline board (Discovery → Applied → … → Hired / Rejected / Ghosted). That board is the
  textbook use case: optimistic **stage transitions** that feel instant, plus **auto Realtime sync** so a
  Gmail/Calendar-scraper-driven Edge Function stage change shows up live without hand-written subscription
  code. There's **no TanStack dependency today** (verified in `package.json`), so this is a genuine option,
  not something you're already running. The **no-SSR caveat is a non-issue** here — the app is a Vite SPA.
- **Concrete change (narrow, spike-only — do not adopt in prod while alpha):**
  1. Time-boxed spike on a branch off `ai/daily-suggestions`, scoped to **`src/features/applications/`**
     only, behind a feature flag. Model **one** collection (applications) and wire the board's optimistic
     stage transition through it.
  2. **Preserve the non-negotiables** (this is why it's TRACK, not IMPLEMENT): keep the **single client**
     (`src/lib/supabase.ts`) as the only DB entry point; ensure every optimistic stage change still writes
     an **`application_events`** row server-side (event-sourcing rule #4) — optimistic UI must not bypass the
     server-side event append; confirm **RLS + `user_id` scoping** still fully constrain the synced
     collection.
  3. If the spike holds, **write an ADR** (`docs/adr/012-tanstack-db-optimistic-pipeline.md`) capturing the
     rollback/consistency model vs. the current raw-`supabase-js` approach **before** any real adoption.
- **Recommended action:** **TRACK.** Alpha maturity + an architectural change that touches three
  non-negotiables (single client, event-sourcing, RLS/user-scoping) means it needs an ADR and a spike, not a
  drop-in. Revisit when it reaches beta/stable.
- **Source(s):** Supabase — *Developer Update - July 2026*, **Jul 9 2026**
  (supabase.com/changelog/47796-developer-update-july-2026); Supabase launch post on X (Jul 2026); repo
  `supabase/tanstack-db` (README) — all corroborate features + alpha status.
