## SUGGESTION CARDS

### 1. Supabase stops auto-granting Data API roles on **all existing projects** 2026-10-30 — 18 days out  [Recommend: IMPLEMENT]
**What's new.** The deadline phase of the Data API exposure change now applies to existing projects, not just new ones. New `public` tables will exist but be unreachable via `supabase-js`/PostgREST until an explicit Postgres `GRANT` is issued; RLS behaviour is unchanged, and Postgres checks grants *before* RLS, so a missing grant blocks access no matter how correct the policy is. PostgREST returns `42501 permission denied for table <name>`. Owner/admin email notices went out 2026-09-23 and go out again 2026-10-23.
**Why it matters for BKT AI-Apply.** Every table behind the pipeline (`applications`, `application_events`, `documents`, job corpus, Prospector feeds) is read through the Data API via `src/lib/supabase.ts`. Any migration that creates a `public` table after Oct 30 — including ones written by an agent on a feature branch — produces a table that passes `pnpm validate` and then 403s at runtime. This is the single highest-severity dated item in this run. Advances **S47**, which covered the project *setting*; this is the platform-wide deadline.
**Concrete change.** (a) Audit: `rg -n "CREATE TABLE" supabase/migrations/` and confirm each `public` table has matching `GRANT` statements. (b) Add the grant block to the migration template so it ships with every new table:
```sql
GRANT SELECT ON public.<t> TO anon;
GRANT SELECT, INSERT, UPDATE, DELETE ON public.<t> TO authenticated;
GRANT SELECT, INSERT, UPDATE, DELETE ON public.<t> TO service_role;
ALTER TABLE public.<t> ENABLE ROW LEVEL SECURITY;
```
(c) Opt in early on a Supabase **branch** first, not production, to surface failures under CI rather than after Oct 30. (d) Check Security Advisor → Data API exposure badge, which flags affected tables with remediation SQL until Oct 30. (e) Add a non-negotiable to `CLAUDE.md`: "every new `public` table ships GRANTs + RLS in the same migration." Tier 2 — propose before applying to a live project.
**Source.** Supabase Changelog / Discussion #45329, "Breaking Change: Tables not exposed to Data and GraphQL API automatically" — rollout dates 2026-04-28, 2026-05-18, 2026-05-30, **2026-10-30**.

### 2. Playwright 1.64.0 (2026-10-07) — the 1.60→1.64 upgrade is now forced by a breaking change  [Recommend: IMPLEMENT]
**What's new.** 1.64.0 published to npm `latest` 2026-10-07T20:42Z. **Why it matters for BKT AI-Apply.** `playwright.uat.config.ts` uses `devices['Desktop Chrome']`, so the `screen` change alters what Tailwind v4 responsive breakpoints resolve to inside the UAT run — layout-sensitive assertions and any future screenshot baselines shift. Staying on 1.60.0 is no longer the low-risk option: it is four minors of accumulated UAT capability (ariaSnapshot JSON, `locator.visible()`, test locks, trace aria snapshots, `getByRef`, `within()`) behind, and the breaking change has to be absorbed once regardless. Supersedes **S106**, **S111**, **S214** as a single consolidated action.
**Concrete change.** Pin both deps exactly in `package.json`: `"@playwright/test": "1.64.0"`, `"playwright": "1.64.0"`. Then `pnpm install && pnpm exec playwright install --with-deps chromium && pnpm test:uat:smoke`, and triage the three breaking changes before running `pnpm test:uat:full`. Keep it to one PR touching `package.json`, `pnpm-lock.yaml`, and whatever assertions the `screen` change breaks — no config refactor in the same change. Tier 2 (dependency upgrade).
**Source.** Playwright release notes v1.64; npm registry publish timestamp for `@playwright/test@1.64.0`.

### 4. Playwright 1.64 `page.getByRef()` closes the aria-snapshot → act loop for AI-UAT  [Recommend: TRACK]
**What's new.** `page.getByRef('e2')` resolves an element from an aria ref emitted by `page.ariaSnapshot()` in `'ai'` mode. `page.content()`/`frame.content()` gain `includeShadow`, serialising open shadow roots as declarative shadow DOM.
**Why it matters.** The AI-UAT agent in `e2e/ai-uat/` currently has to translate a snapshot back into a selector, which is where non-deterministic agent runs go wrong. **Source.** Playwright release notes v1.64 (`page.getByRef()`, `includeShadow`).
