## New suggestion cards

### 1. S124 — Raise unattended-loop CLI floor to `2.1.224` (sandbox deny-bypass + long-path session fix) — **[Recommend: IMPLEMENT]**
- **What's new:** Claude Code **2.1.224** (Aug 7 2026) fixes three defects in the exact sandbox/session line this repo's unattended runs depend on: (a) **sandbox filesystem deny entries written with a trailing slash** (e.g. `denyRead: "~/.aws/"`) were **silently bypassable on Linux and macOS**; (b) **long (>200 char) project paths** could resolve to *another* project's session directory under a shared sanitized prefix — corrupting `session list / rename / fork / delete / /resume`; (c) **sandbox violation details never appeared in Bash tool results**, so the agent couldn't see which file/network access was denied or why.
- **Why it matters for bk-ai-apply:** This is the direct continuation of the S115→S119→S121 floor-bump lineage. The trailing-slash bypass is a real containment hole for any unattended `/loop` that relies on `denyRead`/`denyWrite` to keep credential files out of reach. The long-path fix matters concretely here — this project's Codespaces/session paths are extremely long and Windows-rooted; fork/resume cross-contamination in a `/dispatch` wave would be silent data corruption. Sandbox-violation visibility makes unattended failures debuggable instead of opaque.
- **Concrete change (narrow):** In managed settings (the S104 `requiredMinimumVersion` mechanism), set `requiredMinimumVersion: "2.1.224"`. Supersedes the S121 `2.1.223` floor. Audit any `.claude` sandbox config for **trailing-slash `denyRead`/`denyWrite` entries** and normalize them (drop the trailing `/`) as part of the same PR. No auth/secret/CI-credential changes.
- **Source(s):** [Claude Code changelog — 2.1.224, Aug 7 2026](https://code.claude.com/docs/en/changelog).

### 2. S125 — 2.1.224 sandbox credential-masking: `extract`/`onExtractNoMatch`, `decode: "jwt"`+`maskClaims`, `awsPairs`/`sigv4` — **[Recommend: TRACK]**
- **What's new:** New credential-masking options for values that legitimately flow through the sandbox: `extract`/`onExtractNoMatch` for **structured env values**, `decode: "jwt"` with `maskClaims` for **JWT-aware masking**, and `awsPairs`/`sigv4` for **AWS SigV4 re-signing**. These require `network.tlsTerminate` and are honored only from user, managed, or `--settings`.
- **Why it matters for bk-ai-apply:** Extends the S103 (block credential-file reads) / S115 (credential mask mode) line from "hide the file" to "mask structured secrets and JWT claims *in flight*." Relevant because unattended `/loop`/edge-function work touches Supabase **JWTs** and publishable/secret API keys (S74) — JWT-claim masking is the right primitive if any tool egress ever carries them.
- **Concrete change:** None yet — **TRACK**. Adoption requires standing up `network.tlsTerminate` (a heavier sandbox posture than the repo runs today), so this is a design note, not a drop-in. Revisit if/when unattended runs need outbound calls that carry Supabase JWTs.
- **Source(s):** [Claude Code changelog — 2.1.224, Aug 7 2026](https://code.claude.com/docs/en/changelog).

### 3. S126 — 2.1.224 removes the 200-subagent/session cap + adds cross-session `SendMessage`/`ListAgents` + `crossSessionInbound`/`dialogExpiry` — **[Recommend: TRACK]**
- **What's new:** The **200-subagent-per-session spawn cap is removed** (concurrency/depth limits still apply), so long-running sessions no longer refuse new agents. Sessions can now **message each other across machines** (`SendMessage` + `ListAgents`, macOS/Linux), and new `crossSessionInbound`/`dialogExpiry` settings **hold cross-session messages sent to a bypassed-permissions session for approval** while auto-delivering to others.
- **Why it matters for bk-ai-apply:** Raises the fan-out ceiling for a long-running unattended `/loop`/`/dispatch` wave (updates the mental model behind S67/S86/S99 — the practical limiter is now `MAX_CONCURRENT_SUBAGENTS`, not a hard 200 cap). `crossSessionInbound` is the safety-relevant piece: it prevents an unattended, permission-bypassed `/loop` session from silently acting on injected cross-session messages — it gates them for approval. The cross-machine `SendMessage` primitive is macOS/Linux only, so not directly usable from JB's Windows/Codespaces host today.
- **Concrete change:** None yet — **TRACK**. When `/dispatch` is authored in-repo (S06), design its wave protocol around `MAX_CONCURRENT_SUBAGENTS` + `crossSessionInbound` approval-gating rather than the old cap.
- **Source(s):** [Claude Code changelog — 2.1.224, Aug 7 2026](https://code.claude.com/docs/en/changelog).

### 4. S127 — 2.1.224 `archive` plugin source: install plugins from a zip over HTTPS with optional SHA-256 pinning — **[Recommend: TRACK]**
- **What's new:** A new `archive` plugin source lets you **install a plugin from a zip over HTTPS without git or npm**, with **optional SHA-256 pinning**.
- **Why it matters for bk-ai-apply:** Gives S15 (package the agent roster as a versioned plugin) a **supply-chain-hardened distribution path** that doesn't require a marketplace repo or npm — a pinned zip URL is immutable and verifiable, matching the SHA-pinning discipline already carded for gh-aw (S16/S113). - **Concrete change:** None yet — **TRACK**; contingent on S15 (roster-as-plugin) actually being built. Note the SHA-256 pin option as the intended install mode when it is.
- **Source(s):** [Claude Code changelog — 2.1.224, Aug 7 2026](https://code.claude.com/docs/en/changelog).
