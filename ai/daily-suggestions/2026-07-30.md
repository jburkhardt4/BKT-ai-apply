- **Source:** microsoft/playwright — *Release v1.62.0* ("WebP screenshots"), **Jul 24 2026**.

### 4. `AbortSignal` on actions & web-first assertions — cooperative wall-clock hard-stop for live AI-UAT  [S109]
**[Recommend: TRACK]**  ·  Theme 1 · additive to **S75** (test.abort route-guard) + **S72** (autonomy gates)

- **What's new:** Playwright **1.62.0** adds a `signal` option (accepting an `AbortSignal`) to most operations
  and web-first assertions, letting you cancel long-running actions, navigations, waits, and assertions
  cooperatively (default timeout still applies; pass `timeout: 0` to rely solely on the signal).
- **Why it matters for bk-ai-apply:** the live AI-UAT run (Browserbase agent + Playwright fallback) can hang on
  a wrong element or a never-arriving Realtime update, burning Browserbase minutes and ANTHROPIC budget. A
  single `AbortController` per scenario gives the run a **wall-clock budget** and a clean cancel — a finer-grained
  complement to S75's route-level `test.abort()` and a concrete lever for the S72 autonomy "hard-stop" gate.
- **Concrete change:** in `e2e/ai-uat/_helpers/setup.ts`, create `const ac = new AbortController()` with a
  `setTimeout(() => ac.abort(), BUDGET_MS)` per scenario and thread `ac.signal` into the Playwright-fallback
  waits/assertions; surface the budget as an env var (`AI_UAT_STEP_BUDGET_MS`). Requires S106.
- **Source:** microsoft/playwright — *Release v1.62.0* ("Cancel operations with AbortSignal"), **Jul 24 2026**.
- **Recommended action:** **TRACK** — small, high-value reliability/cost guard; gated on the S106 bump.

### 5. Stagehand 3.7 `setDomainPolicy()` — pin the AI-UAT browser agent to app + Supabase origins  [S110]
**[Recommend: TRACK]**  ·  Theme 1 / security · rides **S05/S95** (v2→v3 upgrade) · browser-layer peer of **S98**

- **What's new:** Stagehand **3.7.0** (**Jul 13 2026**) adds `context.setDomainPolicy({ allowedDomains | blockedDomains })`
  — allowlist/blocklist the domains the agent may visit; Stagehand **auto-closes any popup** that tries to
  violate the policy.
- **Why it matters for bk-ai-apply:** the Browserbase AI-UAT agent in `makeStagehand()` drives a live origin
  (`AI_UAT_BASE_URL` / the `*-5173.app.github.dev` Codespace / Vercel prod). Nothing today stops the agent from
  following an off-app link, an OAuth popup, or injected content to a third-party origin during an unattended
  run. A domain allowlist keeps it on the app + its backends — a **deny-by-default navigation** guard at the
  browser layer that mirrors S98's CC-sandbox egress allowlist and reinforces the repo's security-first posture.
- **Concrete change (with the S05 v3 upgrade; repo is `^2.0.0`):** right after Stagehand init in
  `makeStagehand()`, call
  `await stagehand.context.setDomainPolicy({ allowedDomains: [new URL(UAT_BASE_URL).host, '*.supabase.co', '*.browserbase.com'] })`;
  add a smoke assertion that a link to an external host is blocked. Pin Stagehand ≥ 3.7 (latest 3.7.2).
- **Source:** Browserbase Changelog — *"Domain policies in Stagehand 3.7,"* **Jul 13 2026**.
- **Recommended action:** **TRACK** — rides the open S05/S95 upgrade; no standalone install. IMPLEMENT-ready the
  moment the repo is on Stagehand v3.
