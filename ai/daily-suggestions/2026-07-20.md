## Suggestion Cards

### 1. Cover the file-drop upload zones with Playwright `locator.drop()` — [Recommend: IMPLEMENT]
- **What's new:** Playwright **1.60** added **`locator.drop()`** — it simulates an *external* drag-and-drop
  of files or clipboard-like data onto an element, dispatching `dragenter`/`dragover`/`drop` with a
  synthetic `DataTransfer` in page context. Cross-browser, "great for testing upload zones." **Ships in the
  repo's pinned `1.60.0` — nothing to upgrade.**
- **Why it matters for bk-ai-apply:** the app has **two** external drop zones that the suite never
  exercises — `DocsScreen.tsx` (resume/cover-letter/doc upload → the documents + auto-apply path) and
  `IngestionPage.tsx` (CSV ingestion). Both use hand-rolled `onDragOver`/`onDrop` + a hidden `type="file"`
  input; grep confirms **zero** `.drop()` coverage in `e2e/`. A broken drop handler silently blocks an
  upstream pipeline input, and today only the click-to-browse path (if any) is testable without brittle
  manual `DataTransfer` plumbing. `drop()` gives deterministic, cross-browser coverage of the drag path.
- **Concrete change (narrow, test-only):** add a spec (e.g. `e2e/doc-builder.spec.ts` already exists —
  extend it, and add an ingestion case) that resolves each drop zone and calls
  `await page.locator(<zone>).drop({ files: { name: 'resume.pdf', mimeType: 'application/pdf', buffer } })`
  (and a `.csv` for `IngestionPage`), then asserts the resulting preview/upload state. **Note:** the
  Prospector column reorder in `ProspectorSearchResults.tsx` is *intra-page* native HTML5 DnD — that still
  needs `locator.dragTo()`, **not** `drop()`. No dep bump (1.60.0); no secrets/CI changes.
- **Source:** [Playwright release notes — Version 1.60 · Drop API](https://playwright.dev/docs/release-notes) (2026).

### 2. Record a network audit trail for live AI-UAT with `tracing.startHar()` — [Recommend: TRACK]
- **What's new:** Playwright **1.60** exposes HAR recording as a first-class tracing API —
  **`context.tracing.startHar()` / `stopHar()`** with the same `content`/`mode`/`urlFilter` options as
  `recordHar`, returning a `Disposable` so a recording scopes cleanly with `await using`. **Already in the
  repo's `1.60.0`.**
- **Why it matters for bk-ai-apply:** AI-UAT drives a **non-deterministic** agent (Browserbase/Stagehand)
  against **live** targets, and there is currently **no captured record** of exactly which network calls
  (PostgREST, Edge Functions) the agent made in a run. A scoped HAR recorded per test is a complete,
  reviewable audit trail of what actually happened on a real environment — directly serving your
  "release safety / auth integrity as first-class" rule, and complementing the console/page-error gate
  (S70) and the `test.abort()` route-guard (S75). Distinct from **S49** (`routeFromHAR` *replay*) and
  **S64** (WebSocket-in-HAR): this is **recording for audit**, not replay.
- **Concrete change (narrow):** in `e2e/ai-uat/_helpers/setup.ts`, wrap each AI-UAT with
  `await using har = await context.tracing.startHar('ai-uat.har', { urlFilter: <supabase-project + app origin> })`
  and attach the HAR to the report **on failure only** (bound artifact size). Decide a short retention
  window. No dep bump; no secrets. Pairs with the existing `video: 'retain-on-failure'` policy.
- **Source:** [Playwright release notes — Version 1.60 · HAR recording on Tracing](https://playwright.dev/docs/release-notes) (2026).

### 3. Set a Claude Code **≥ 2.1.214** floor for unattended runs (scheduled-task trust + permission/hook glob hardening) — [Recommend: IMPLEMENT]
- **What's new:** Claude Code **2.1.214 (Jul 18, 2026)** shipped a security/permissions release that
  directly affects unattended, scheduled sessions:
  - **Fixes scheduled tasks refusing their own configured prompt as untrusted input** — the fired prompt is
    now delivered as the session's assigned task. (This *is* how this daily routine runs.)
  - **Tightens permission-rule glob semantics:** single-segment `dir/**` allow rules like `Edit(src/**)` no
    longer auto-approve nested `dir/` **anywhere** in the tree — only `<cwd>/dir`. Hook `if:` single-segment
    `dir/**` likewise now matches only `<cwd>/dir` (**use `**/dir/**` for any-depth**; `deny`/`ask` keep
    any-depth).
  - **Fixes hooks with exit code 2 not blocking** when the hook's stdout JSON fails schema validation; plus
    multiple Bash permission-check **fail-closed** fixes (commands > 10,000 chars now always prompt; FD-redirect
    forms; a Windows PowerShell 5.1 bypass).
- **Why it matters for bk-ai-apply:** the daily routine and `/loop` run **unattended**. The scheduled-task
  fix means this routine's own prompt is reliably delivered on ≥ 2.1.214. The glob-semantics changes are a
  **prerequisite** to correctly encoding the non-negotiables as hooks/permission rules (S14/S66): an
  `Edit(src/**)` allow rule authored under the old semantics behaves differently now, and a hook that
  "should block" could previously slip through. Genuine gap: repo has **no `.claude/settings.json`** and
  **no documented CC version floor** — so documenting this *before* building the guardrails prevents a false
  sense of safety.
- **Concrete change (doc-only; no secrets/env/CI-cred changes):** add an **"Unattended-run toolchain floor"**
  note to `docs/conventions/agent-protocol.md` — require **Claude Code ≥ 2.1.214** for scheduled/`/loop`
  runs; when S14/S66 land `.claude/settings.json`, write allow/hook globs to the **new** semantics
  (`**/dir/**` for any-depth) and verify exit-code-2 hooks actually block. Pairs with **S78** (2.1.212
  budgets) as the combined floor. (Also re-checks the "plugins via `--settings` not loading" regression fix.)
- **Source:** [Claude Code changelog — 2.1.214](https://code.claude.com/docs/en/changelog) (Jul 18, 2026).

### 5. Adopt a "human-written, minimal" rule for `AGENTS.md` / `CLAUDE.md` (2026 empirical research) — [Recommend: TRACK]
- **What's new:** A cluster of **2026** studies on repository context files reports that **LLM-generated**

- **Why it matters for bk-ai-apply:** the repo carries a lot of agent context — root `AGENTS.md`,

  `AGENTS.md` (S79). As that surface grows, this is a direct, evidence-based guardrail for Theme 3
  (centralizing knowledge/context): don't auto-generate context; keep each file minimal, command-first,
  human-authored, and scoped. It sharpens the generic "precision audit" (S08) with 2026 data and reinforces
  the JIT-context principle (S72) and pointer-repair/prune work (S48/S60). **Additive to S08/S79, not a repeat.**
- **Concrete change (principle + light audit):** add a one-paragraph **"Context-file authoring rule"** to
  `AGENTS.md` / `docs/conventions/agent-protocol.md` — human-written, minimal, copy-pasteable commands,
  explicit boundaries, **no AI-generated overviews**; hold every new per-feature `AGENTS.md` (S79) to that
