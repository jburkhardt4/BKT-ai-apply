## Suggestion cards

All five come from one corroborated primary source: the official **Claude Code changelog, 2.1.233 (Aug 14 2026)** — the first release past the ledger's 2.1.232 (S143/S144). Verified against the live changelog page: 2.1.233 is the current head.

### 1. Claude Code 2.1.233 — raise unattended `/loop` `/dispatch` CLI floor to `>=2.1.233`  `[Recommend: IMPLEMENT]`  *(Theme 2 / release safety)*
- **What's new:** 2.1.233 (Aug 14) fixes **Windows NT `\??\` device-prefix paths bypassing UNC path validation — an NTLM credential-leak vector**; fixes **idle Linux sessions sometimes pinning one CPU core at 100% when sandboxing is enabled**; and fixes a **2.1.232 auto-mode regression** that repeatedly stopped for manual approval on ordinary `cd <dir> && <command> > file` Bash commands.
- **Why it matters for bk-ai-apply:** JB's unattended footprint spans both platforms — Codespaces (**Linux**, where the idle-CPU peg wastes an unattended runner) and a **Windows** workstation (where the `\??\`/NTLM path is a real credential-exfil vector for an agent processing untrusted job-listing/email content). The auto-mode regression fix directly restores hands-off `/loop` throughput that 2.1.232 broke. This is the established security/reliability floor, superseding S143's 2.1.232 target.
- **Concrete change (narrow):** One line — set `requiredMinimumVersion: "2.1.233"` in managed/`.claude/settings.json` (supersedes S143). **Queued** behind landing that settings file (S14/S104) + the GitHub connector for the commit. No agent/logic edits.
- **Source(s):** [Claude Code changelog — code.claude.com](https://code.claude.com/docs/en/changelog) (2.1.233, Aug 14 2026).

### 2. Claude Code 2.1.233 — Todo/Task tools **removed on default models**; audit `/loop` `/dispatch` progress tracking  `[Recommend: IMPLEMENT]`  *(Theme 2 — priority)*
- **What's new:** As of 2.1.233, the **Todo/task-tracking tools (`TaskCreate`/`Get`/`Update`/`List`, `TodoWrite`) are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models**. Re-enable with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`.
- **Why it matters for bk-ai-apply:** **Opus 5 is JB's default** (S97 re-baselined ADR-010/model-routing onto it). Any `/loop` `/routines` `/dispatch` step or `.claude/agents/*` persona that leans on `TodoWrite`/`Task*` for progress tracking or wave-status **silently loses that tool on the default model** — degrading orchestration and unattended observability with no error. This is a genuine gap: the snapshot's orchestrator/agents predate the change and were never audited for it. It also nudges toward the file-based progress discipline already tracked (S130 `claude-progress.txt`/`feature_list.json`, S132 evaluator harness), which does not depend on the built-in tools.
- **Concrete change (narrow):** (a) Grep `.claude/agents/*` + any authored `/loop` `/routines` `/dispatch` for `TodoWrite`/`TaskCreate`/`TaskUpdate`/`TaskList` reliance. (b) Decide one of two: set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` in the unattended env / `.claude/settings.json` to preserve current behavior, **or** migrate progress tracking to the file-based harness (S130/S132). Document the choice in ADR-010's model-routing notes. No product-code change.
- **Source(s):** [Claude Code changelog — code.claude.com](https://code.claude.com/docs/en/changelog) (2.1.233, Aug 14 2026).

### 3. Claude Code 2.1.233 **partially reverts** the 2.1.232 Bash permission tightening (corrects S143)  `[Recommend: TRACK]`  *(Theme 2 / release safety)*
- **What's new:** 2.1.233 **reverts the 2.1.232 Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (`< file`)** — "a narrower version will return in a later release." The rest of the 2.1.232 security set (PowerShell `$PSDefaultParameterValues` bypass, nested-git trust inheritance, Linux sandbox protected-path/`/tmp` socket hardening) **remains in force**, and the new `\??\`/NTLM fix (card 1) is added on top.
- **Why it matters for bk-ai-apply:** S143 flagged the 2.1.232 Bash tightening (incl. `< file` now permission-checked) as a BREAKING/security change to design permission rules around. That behavior was rolled back **one day later** — so any hardening notes or `.claude/settings.json` permission rules must **not** assume the 2.1.232 `< file`/Cygwin-symlink semantics are permanent. Floor still moves to 2.1.233 (card 1): it is strictly safer than 2.1.232 on the fixes that stuck.
- **Concrete change (narrow):** Annotate the unattended-loop hardening notes (and S143's backlog entry) that the `< file`/Cygwin-symlink tightening is temporarily withdrawn; re-evaluate when the "narrower version" ships. No config action beyond the card-1 floor bump.
- **Source(s):** [Claude Code changelog — code.claude.com](https://code.claude.com/docs/en/changelog) (2.1.233, Aug 14 2026).

### 4. Claude Code 2.1.233 — `CLAUDE_CODE_TOOL_MEMORY_LIMIT` memory-cgroup guard for unattended Linux `/loop`  `[Recommend: TRACK]`  *(Theme 2 / unattended safety)*
- **What's new:** 2.1.233 adds **opt-in memory cgroup support for Bash tool commands on Linux** via `CLAUDE_CODE_TOOL_MEMORY_LIMIT`, "so a runaway build can't stall the session."
- **Why it matters for bk-ai-apply:** The unattended `/loop` runs `pnpm build` / `pnpm validate` / Playwright in Codespaces (**Linux**). A memory-runaway (Vite/tsc/`playwright install`, or a bad dep) currently can wedge the whole unattended session with no recovery. A per-command memory ceiling fails the offending Bash command instead of the session — additive to the sandbox-hardening line (S44/S98/S103/S125) and complementary to the 2.1.229 container-CPU-limit fix (S140).
- **Concrete change (narrow):** Once floor ≥2.1.233 lands, set `CLAUDE_CODE_TOOL_MEMORY_LIMIT` (e.g. a conservative cap below the Codespace's RAM) in the unattended/Codespaces env or `.claude/settings.json`. Verify a normal `pnpm validate` fits under the cap before enabling. No code change.
- **Source(s):** [Claude Code changelog — code.claude.com](https://code.claude.com/docs/en/changelog) (2.1.233, Aug 14 2026).

### 5. Claude Code 2.1.233 — `claude plugin validate` now lints bare `.claude/skills` frontmatter + bundled-skill shadow fix  `[Recommend: TRACK]`  *(Theme 2 / skill hygiene — extends S28/S116)*
