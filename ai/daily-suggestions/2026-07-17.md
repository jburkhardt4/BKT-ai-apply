## Suggestion Cards

### 1. Guard AI-UAT against live environments with Playwright `test.abort()`  — [Recommend: TRACK]
- **What's new:** Playwright **1.60** adds `test.abort(message?)`, which fails the current test
  immediately from a fixture, hook, or `route` handler — meant for "detected an unrecoverable misuse,
  stop now."
- **Why it matters for bk-ai-apply:** `playwright.uat.config.ts` points the Browserbase/Stagehand
  agent at **live** targets (`AI_UAT_BASE_URL`, or the Codespace `…-5173.app.github.dev` URL, or prod
  `bkt-ai-apply.vercel.app`). A non-deterministic agent can wander into a **mutating** request against
  a real environment. A route-level abort converts that from a silent side effect into an immediate,
  logged hard-stop — directly serving your "release safety / auth integrity as first-class" rule.
- **Concrete change (narrow):** Add a shared fixture in `e2e/ai-uat/` that installs
  `await page.route('**/**', …)` and calls `test.abort('AI-UAT must not mutate <endpoint> on a live target')`
  + `route.abort()` for disallowed patterns (e.g. non-`GET` to `…/rest/v1/`, or any hit to
  `…/functions/v1/submit*`). Arm it only when target is `prod`. `e2e/` already uses `page.route()`
  (extension specs), so this is idiomatic. Requires `@playwright/test` ≥ 1.60 (confirm/raise the pin).
- **Source:** [Playwright release notes — Version 1.60](https://playwright.dev/docs/release-notes) (2026).

### 3. Re-architect `/dispatch` waves on `/fork` background sessions + `/subtask`  — [Recommend: TRACK]
- **What's new:** Claude Code **2.1.212 (Jul 17, 2026)**: `/fork` now copies the conversation into a
  new **background** session (its own row in `claude agents`) while you keep working; the in-session
  subagent it used to launch is renamed **`/subtask`**.
- **Why it matters for bk-ai-apply:** `/dispatch` wave orchestration (the `wave1/2/3-dry-run` prompts +
  `orchestrator.md`) currently fans out via in-session subagents that block the parent and are hard to
  observe. `/fork` gives each parallel workstream an **independent, observable, resumable** background
  session — much closer to your "waves" model — while `/subtask` stays for lightweight in-session help.
  Better parallelism and auditability for unattended runs.
- **Concrete change (narrow):** In `docs/conventions/agent-protocol.md` + the orchestrator agent def,
  specify that `/dispatch` launches each wave item as a `/fork` background session (track IDs via
  `claude agents --json`, collect on completion) and reserves `/subtask` for in-session helpers.
  Pilot against `wave1-dry-run.prompt.md`.
- **Source:** [Claude Code changelog — 2.1.212](https://code.claude.com/docs/en/changelog) (Jul 17, 2026).

### 4. Harden the unattended `/loop` for Claude Code 2.1.212  — [Recommend: IMPLEMENT]
- **What's new:** 2.1.212 (Jul 17, 2026) adds runaway-loop **budgets** —
  `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` (default 200) and
  `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` (default 200) — auto-backgrounds MCP calls > 2 min
  (`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`), and **fixes two safety bugs**: a `continue:false` hook halt
  being **dropped** when a tool fails mid-stream, and **plan mode auto-running** file-modifying Bash
  (`touch`/`rm`) **without a prompt**.
- **Why it matters for bk-ai-apply:** the daily routine and `/loop` run **unattended**. Until 2.1.212,
  hook-based enforcement of the non-negotiables (S14) could be silently dropped, and plan mode could
  mutate files unprompted — so the guardrails weren't fully trustworthy. The budgets bound the
  cost/blast-radius of a runaway delegation or search loop. This is a genuine gap: no budgets are
  documented anywhere in the repo, and there is no `.claude/settings.json`.
- **Concrete change (narrow — no secrets/env/CI-credential changes):**
  (a) Require Claude Code **≥ 2.1.212** for unattended runs;
  (b) add an **"Unattended-loop guardrails"** subsection to `docs/conventions/agent-protocol.md` with
  explicit budgets (e.g. `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION=40`,
  `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=60`) and set them in the wrapper that launches `/loop`;
  (c) note that PreToolUse `ask` / `continue:false` hooks are now reliable → proceed to encode the
  non-negotiables as hooks (S14).
- **Source:** [Claude Code changelog — 2.1.212](https://code.claude.com/docs/en/changelog) (Jul 17, 2026).

### 5. Nested, per-feature `AGENTS.md` under `src/features/*`  — [Recommend: TRACK]
- **What's new:** The 2026 `AGENTS.md` guidance (and Codex's own monorepo usage — 88 nested files)
  formalizes the **nearest-file** model: root holds cross-cutting rules; subtree files override with
  local specifics; **split** once a file passes ~150–200 lines; keep each file **scoped** to its directory.
- **Why it matters for bk-ai-apply:** the repo has a **single** root `AGENTS.md` (plus `CLAUDE.md`,
  `docs/conventions/`) carrying all conventions. As feature areas diverge (`ai-agent`, `applications`,
  `auto-apply`, `jobs`, `settings`), a nearest-file model puts the right context in front of an agent
  editing that subtree — event-sourcing + stage rules for `applications`, model-routing for `ai-agent` —
  without bloating the root or relying on recall. This is **additive** to the single-SoT idea (S39), not
  a replacement.
- **Concrete change (narrow):** Add short, **scoped** `src/features/<area>/AGENTS.md` files (10–30 lines)
  that **link back** to the canonical `docs/` rule for that area and state only local specifics; keep
  root `AGENTS.md`/`CLAUDE.md` for cross-cutting non-negotiables. Audit for scope discipline (no
  cross-feature rules in a feature file).
- **Source:** [OpenAI Codex — AGENTS.md guide](https://developers.openai.com/codex/guides/agents-md) (2026); [AGENTS.md monorepo playbook, 2026](https://www.codegateway.dev/en/blog/agents-md-playbook-2026).
