### 3. Claude Code 2.1.219 — `sandbox.network.strictAllowlist`: deny-by-default egress for the unattended `/loop` — [Recommend: TRACK]

- **What's new:** 2.1.219 (Jul 24 2026): *"Added `sandbox.network.strictAllowlist` setting to deny
  non-allowlisted hosts for sandboxed commands without prompting."*
- **Why it matters for bk-ai-apply:** The unattended `/loop` runs sandboxed shell commands (**S44**
  sandboxing; **S89** `sandbox.filesystem.disabled`). Outbound network from an autonomous loop is a real
  exfiltration surface — a prompt-injection in a fetched page or tool result could `curl` data to an
  attacker host. `strictAllowlist` makes egress **deny-by-default** *without prompting*, which is exactly
  what an unattended loop needs (no human to answer the prompt, and the safe default is "block"). It
  tightens the same sandbox-hardening line as S44/S89 rather than duplicating it.
- **Concrete change (narrow):** When `.claude/settings.json` lands (**S14**), set
  `sandbox.network.strictAllowlist: true` and enumerate the allowlist to the four hosts the loop actually
  needs: the Supabase project host, the npm registry, `github.com`/`api.github.com`, and the Anthropic API.
  **Gated on S14** (no settings file in the snapshot) → TRACK.
- **Source(s):** Claude Code changelog **2.1.219**, Jul 24 2026 (code.claude.com/docs/en/changelog);
  digitalapplied.com "Claude Code guardrails on its own agent fleets" (2026).
