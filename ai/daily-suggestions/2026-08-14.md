### 2. Claude Code 2.1.232 — subagent **fork-by-default** + background-by-default reshapes `/dispatch` `/loop` design  `[Recommend: TRACK]`  *(Theme 2 — priority)*
- **What's new:** `subagent_type: "fork"` is now **on by default**, and launching non-teammate agents in interactive sessions now **runs them in the background by default**. A fork **inherits the parent's full conversation context and prompt cache** and always runs on the parent's model (a `model` override is ignored); its tool output stays out of the parent context. Revert with `CLAUDE_CODE_FORK_SUBAGENT=0`. The Agent-tool description the model sees is rewritten accordingly.
- **Why it matters for bk-ai-apply:** This changes the economics of the wave-delegation model behind S06/S07/S86/S99 and pairs directly with S141's prefix-stagger caching. "Fork inherits full conversation + prompt cache" is exactly the context-rewrite / cache-miss pain the orchestrator hits handing tasks to subagents — but it also means fork **ignores per-subagent model overrides**, which interacts with ADR-010 model-routing (a routed subagent that must run on a *cheaper/different* model should be a fresh spawn, not a fork). The `/dispatch` wave spec (still unbuilt) should be authored to choose fork vs fresh-spawn deliberately, and to account for background-by-default execution.
- **Concrete change (narrow):** Design input only — no repo change today. When S06 `/dispatch` `/loop` are authored, document the fork-vs-spawn decision rule (fork for same-model context-carrying investigation; fresh spawn when ADR-010 routes to a different model) and decide whether unattended headless runs set `CLAUDE_CODE_FORK_SUBAGENT` explicitly for determinism. Fold into the S130/S132 harness design.
- **Source(s):** [CC v2.1.230–v2.1.232 summary — DevelopersIO](https://dev.classmethod.jp/en/articles/20260814-cc-updates-v2-1-232/) (Aug 14 2026); [Claude Code changelog — code.claude.com](https://code.claude.com/docs/en/changelog) (Aug 13 2026).
