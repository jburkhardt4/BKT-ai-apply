### 2. Claude Code 2.1.217 reverses nested-subagent defaults — `/dispatch` wave design needs updating — [Recommend: IMPLEMENT]

- **What's new:** Claude Code **2.1.217** (Jul 21 2026): *"Changed subagents to no longer spawn nested
  subagents by default; set `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` to allow deeper nesting."* Same release
  adds a cap on concurrently-running subagents (**default 20**, override via
  `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`) *"so one message can't fan out unbounded background agents"*, and
  fixes `--max-budget-usd` not stopping background subagents — the cap now denies new spawns **and halts
  running background agents**.
- **Why it matters for bk-ai-apply:** **S67** (backlog, PROPOSED) recommended nested sub-agents up to 5
  levels for `/dispatch` wave delegation. That default is now **off**. Any wave design that assumes an
  orchestrator subagent can itself delegate will silently flatten — the work still runs, just without the
  intended delegation shape, which is the worst failure mode for an unattended run. The concurrency cap and
  the budget-halt fix are the first real hard stops for runaway fan-out in `/loop` and `/dispatch`.
- **Concrete change (narrow):** (a) require CLI **≥ 2.1.217**; (b) create `.claude/settings.json` (does not
  exist yet) setting `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` explicitly if `/dispatch` relies on nesting, and
  `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` to a deliberate number rather than inheriting 20; (c) add a
  **"Fan-out and delegation limits"** section to `docs/conventions/agent-protocol.md` (currently 69 lines,
  zero coverage of this) recording depth, concurrency, and the `--max-budget-usd` halt semantics; (d) mark
  **S67 as superseded** in `backlog.md`. No secrets, no CI, no auth changes.
- **Source(s):** [Claude Code changelog — 2.1.217](https://code.claude.com/docs/en/changelog), Jul 21 2026.
- **Recommend:** **IMPLEMENT** — verified gap: `agent-protocol.md` has no fan-out section, no
  `.claude/settings.json` exists, and this is a **behavioral reversal** of an item already in the backlog.

- **What's new:** Supabase shipped **Passkeys for Supabase Auth (Beta)** on **May 28 2026** — passwordless,
  phishing-resistant WebAuthn credentials. Supabase Auth stores only the public key; private key material
  stays with the user's authenticator. The **API is experimental, requires explicit opt-in, and may change

  candidate. It also closes a loop with **S53**: Playwright 1.61's virtual WebAuthn authenticator means a

- **Concrete change (narrow):** none. Log against `docs/domain/auth.md` as an evaluated-and-deferred option.
  Revisit when the API leaves beta. Any adoption would need an ADR (auth boundary is a documented

- **Source(s):** [Passkeys for Supabase Auth (Beta) — Supabase
