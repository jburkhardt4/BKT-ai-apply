### 1. Adopt Playwright 1.62 `retryStrategy: 'isolated'` for live AI-UAT  [Recommend: IMPLEMENT]
- **What's new:** Playwright 1.62 (Jul 24 2026) adds `testConfig.retryStrategy`. Default `'immediate'` interleaves retries with the run; the new **`'isolated'`** strategy runs all retries at the very end, one-by-one in a single worker, minimizing cross-test interference — it separates a genuinely *flaky* test from one with a *concurrency* bug.
- **Why it matters for bk-ai-apply:** `playwright.uat.config.ts` drives a **live browser agent** (Stagehand/Browserbase) against prod/preview. Live AI-UAT is the most flake-prone surface you have — network, model latency, shared session state. `'isolated'` gives cleaner pass/fail signal for the release gate without masking real concurrency defects. This is a 1.62 sub-feature the ledger never captured (S106–S114 covered WebP goldens, in-box MCP, AbortSignal, aria-snapshot fix — not retry strategy).
- **Concrete change:** In `playwright.uat.config.ts`, add `retries: 2, retryStrategy: 'isolated'` (keep `e2e`/unit configs on default `'immediate'`). Rides the already-queued **S111** pin to 1.62.1. Verify with `pnpm test:uat` that retried specs run last in a single worker.
- **Source(s):** Playwright v1.62.0 release notes / `TestConfig.retryStrategy` docs (Jul 24 2026); Bug0 "What's new in Playwright 1.62" (Jul 2026).
- **Recommended action:** IMPLEMENT (narrow config addition; queued behind S111 landing + GitHub access).
