- **What's new:** **Trusted Sources for Deployment Protection** (Vercel, **May 13 2026**) lets a protected
  deployment accept **short-lived OIDC identity tokens** from Vercel projects and external services you
  authorize — the caller attaches `x-vercel-trusted-oidc-idp-token` and Vercel verifies signature, claims,
  and environment — **instead of** sharing a long-lived Protection-Bypass-for-Automation secret. Separately,
  **Protection Bypass for Automation now supports multiple secrets** (Jan 13 2026) for rotation and
  per-workflow scoping.
- **Why it matters for bk-ai-apply:** **S35** (IMPLEMENT, still PROPOSED) proposes exactly this pattern —
  AI-UAT reaching a **protected Vercel preview** — but via the classic **long-lived**

  Anthropic / Browserbase secrets, which is precisely the standing-credential exposure JB's "auth integrity
  + release safety as first-class" posture wants to avoid. Trusted Sources swaps the shared secret for a
  **per-run OIDC token minted from the GitHub Actions identity** — strictly better for an unattended UAT
  runner. Adopting it now shapes S35 correctly **before** it's built, at no extra scope.
- **Concrete change (narrow):** none today (S35 isn't implemented yet). When S35 is picked up: configure
