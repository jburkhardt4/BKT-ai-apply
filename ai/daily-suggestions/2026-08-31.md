## 1. [Recommend: IMPLEMENT] CC 2.1.251 security cluster — raise unattended CLI floor to >=2.1.251

**What's new** — 2.1.251 (Aug 28) is the largest security release since 2.1.234, and it lands squarely on the file-access and settings-trust boundaries an unattended `/loop` runs inside. 2.1.252 (Aug 31) is fixes-only.

**Why it matters for bk-ai-apply** — The two highest-severity items defeat controls this routine already relies on:
- **Symlink TOCTOU in Read/Write/Edit** — a symlink swapped inside the working directory *after* the permission check could read or write **outside** the approved location. Every sandbox path item (S44/S98/S103/S124/S125) assumes the check holds.
- **Grep/Glob ignored `Read(...)` deny rules** through symlinked search paths — a deny-rule bypass, i.e. `.env` / Supabase key denies were not enforced on search.
- Plugin-marketplace commands could point **outside** the plugin directory (path traversal) — extends the S163/S127 supply-chain line.
- Project settings could enable **raw API body logging / detailed beta tracing** and bypass an org-pinned OTLP collector — an exfiltration path out of project-scoped config.
- Project `.claude/settings.json` `env` can **no longer** set `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_TMPDIR`, `TMPDIR`/`TMP`/`TEMP`.
- `ANTHROPIC_CUSTOM_HEADERS` from managed/project settings now requires approval when it sets a credential/routing header.
- Bash permission checks auto-approved arithmetic assignments (`OPTIND=1/0`, `RANDOM=2+2`) — now prompt.
- The one-time "make auto mode your default" offer **appeared in unattended sessions** (agent-team teammate panes) where a stray keypress could accept it unread.

**Concrete change** (narrow)
1. `.claude/settings.json` — set `requiredMinimumVersion` to `2.1.251` (mechanism from S104). Supersedes the S159 floor of 2.1.234; running target `>=2.1.252`.
2. Bump the CLI in the scheduled-task/Codespaces env and re-run `claude doctor`.
3. **Regression check against S164**: that card recommended `CLAUDE_CODE_PROJECT_DIR_NAME`. It is a *different* variable and is unaffected, but if any project-scoped `env` block currently sets `CLAUDE_CONFIG_DIR`/`TMPDIR`, 2.1.251 silently stops honoring it — move those to shell or user settings in the same commit.

**Source** — Claude Code changelog, 2.1.251 (Aug 28 2026) and 2.1.252 (Aug 31 2026): https://code.claude.com/docs/en/changelog

## 2. [Recommend: IMPLEMENT] `--restricted` / `CLAUDE_CODE_RESTRICTED=1` — least-privilege mode for read-only agent legs

**What's new** — CC 2.1.248 (Aug 27) added `--restricted` (env `CLAUDE_CODE_RESTRICTED=1`): removes the built-in tools that **run commands or code** and removes `WebFetch` (unless named in `--tools`), keeps file tools **inside the working directory**, **refuses `bypassPermissions`**, and **ignores user, project and local settings files**.

**Why it matters for bk-ai-apply** — This is categorically different from the sandbox line (S44/S98/S103/S125), which *confines* execution. `--restricted` **removes** it. That is the right shape for the read-only legs of the agent roster — `business-analyst`, `context-keeper`, `critical-path`, the audit half of `supabase-security`, and the research phase of this very routine — none of which need to execute anything. It also closes the `bypassPermissions` escape by refusal rather than by policy, which is stronger than the org-policy gap fixed back in S121.

**Concrete change**
- Add `--restricted` to the analysis-only invocations in `.claude/commands/dispatch.md` (or the skill, per S158/S192) and to the research leg of the scheduled routine.
- **Do not** apply it to the build/validate `/loop` — `pnpm validate` needs Bash.
- **Watch the settings tradeoff:** because it ignores project/local settings files, a `--restricted` session will **not** load `.claude/settings.json` — so it inherits neither the S201 version floor nor the S14 hooks. Restricted sessions must be launched with explicit `--tools`/flags, not assumed to inherit repo policy. Record this in the ADR; it is the non-obvious failure mode.

**Source** — Claude Code changelog, 2.1.248 (Aug 27 2026): https://code.claude.com/docs/en/changelog

## 3. [Recommend: IMPLEMENT] `/loop` cost telemetry + first-class prompt-cache TTL settings

**What's new** — 2.1.243 (Aug 25) added a **Loops breakdown to `/usage`** (per-loop run count, total tokens, tokens per run, last run — "so runaway or chatty `/loop` tasks are easy to spot") and the `promptCacheTtl` / `subagentPromptCacheTtl` settings (1-hour cache on the main conversation while subagents stay at 5 minutes). 2.1.248 added `experimental.cacheTtl` (`"5m"` / `"1h"`) to **agent frontmatter**, a per-agent TTL used when no subagent setting is configured.

**Why it matters for bk-ai-apply** — S192 established that `/loop` must run from a fresh session and flagged `ENABLE_PROMPT_CACHING_1H`; these are the supported settings that replace the env-var approach, and the **asymmetry is the point**: the long-lived `/loop` conversation wants 1h, while `/dispatch` fan-out subagents are short-lived and should stay at 5m (paying 1h-cache write premiums on agents that never return is pure waste). The Loops breakdown supplies the feedback signal S06's budget design has never had — until now, "is `/loop` chatty?" was unmeasurable without parsing transcripts.

**Concrete change**
1. `.claude/settings.json`: `"promptCacheTtl": "1h"`, `"subagentPromptCacheTtl": "5m"`.
2. Override per agent via `experimental.cacheTtl` in frontmatter only where a subagent is genuinely long-running (`orchestrator`, `qa-uat`).
3. Add "run `/usage` → Loops breakdown" as an explicit step in the `/routines` weekly review; record the first baseline in `docs/adr/` alongside ADR-010.
4. Sequence **after** S201 (both edit `.claude/settings.json`; land as one commit).

## 4. [Recommend: TRACK] Model-switch hooks + `CLAUDE_CODE_SUBAGENT_MODEL` semantics reversal

**What's new** — 2.1.251 added `PreModelSwitch` and `PostModelSwitch` hook events (**block, confirm, or annotate** a model switch), and `SessionStart` resume hooks now receive **session staleness and estimated re-cache cost**. Separately, 2.1.251 **changed** `CLAUDE_CODE_SUBAGENT_MODEL` from an override of everything to setting the *default*: an agent definition's `model:` and an explicit per-spawn model now **take precedence over it**.

**Why it matters for bk-ai-apply** — ADR-010 / `docs/conventions/model-routing.md` has been enforceable only by convention. `PreModelSwitch` makes it enforceable by hook: a scheduled run that silently drifts off the pinned model can now be **blocked** rather than discovered afterward. The `SUBAGENT_MODEL` reversal is a live correction to the roster's mental model — under the old semantics an env var could quietly flatten every agent's declared `model:`; it now loses to the agent definition. That also softens the S144 caveat (fork-by-default ignoring per-subagent model overrides) into a narrower, fork-specific case rather than a general one.

**Concrete change (when picked up)** — a `PreModelSwitch` hook in `.claude/settings.json` asserting the ADR-010 pin for unattended runs; annotate rather than block for interactive. Re-read `model-routing.md` against the new precedence order (env < agent `model:` < per-spawn) and correct any text written under the old override assumption.

**Source** — Claude Code changelog, 2.1.251 (Aug 28 2026): https://code.claude.com/docs/en/changelog

## 6. [Recommend: TRACK] Auto-mode permission hardening — the `Bash(git * main)` wildcard footgun

**What's new** — 2.1.246 (Aug 25) added a **startup warning for Bash allow rules with a wildcard before the subcommand** (e.g. `Bash(git * main)`) "since they also match options inserted before the subcommand"; added an **Auto mode tab to `/permissions`** for viewing and editing auto-mode classifier rules; fixed auto-mode tool calls being denied as *"temporarily unavailable"* **on very large sessions** (the safety-check deadline now scales with prompt size); and fixed the command sandbox's filesystem configuration **not respecting `--setting-sources`**.

**Why it matters for bk-ai-apply** — S66 put parameterized `Tool(param:value)` permission rules at the center of unattended `/loop`. This is the disclosed footgun in that design: a leading wildcard matches injected *options*, not just the intended subcommand — a real escalation path in exactly the rules a scheduled run leans on. The large-session denial fix matters more than it reads: `/loop` sessions grow, and spurious "temporarily unavailable" denials late in a run are indistinguishable from a policy denial in the transcript. The `--setting-sources` sandbox fix means sandbox config was silently not applying under some invocations — worth a re-verify of any S98/S103 assumptions made from a run that used it.

**Concrete change (when picked up)** — grep every `Bash(...)` allow rule in `.claude/settings.json` for a `*` preceding the subcommand and rewrite to anchor the subcommand first; then open `/permissions` → Auto mode and snapshot the classifier rules into the ADR so the unattended profile is reviewable rather than implicit.
