  (`supabase test db`), with a **test-helpers** package that makes RLS testing first-class:
  `tests.create_supabase_user()`, `tests.authenticate_as()`, and `tests.rls_enabled('public','<table>')`

  claim rests on hand-review. A pgTAP suite turns "RLS is on" into a **proven, regression-gated**
  invariant — the deterministic backstop under Theme 1 that complements S37 (seed data) and S13
  (per-PR branch DBs), and the natural home for the `Supabase-Security` agent's evidence.
- **Concrete change (narrow):** add `supabase/tests/000-setup-tests-hooks.sql` (install
  `pgtap` + `supabase_test_helpers`) and **one** focused test, e.g.

### S42 — Pin visual-snapshot rendering to the **official Playwright Docker image** so baselines are deterministic
- **What's new:** the canonical fix for flaky `toHaveScreenshot` diffs is to generate **and**
  compare baselines **inside the official `mcr.microsoft.com/playwright` image at the exact
  pinned version**, because font hinting, anti-aliasing and system libs differ across
  macOS/Windows/Ubuntu — the same DOM yields a slightly different PNG on a GitHub `ubuntu-latest`
  runner than on a dev box. The community-standard hardening pairs the container with the
  `--font-render-hinting=none` Chromium arg and an OS-tagged `snapshotPathTemplate`.
- **Why it matters for bk-ai-apply:** this is the **missing primitive under the already-tracked
  visual items** (S01 `toHaveScreenshot` gate, S02 hosted visual review, S20 Vitest browser-mode
  snapshots). CI today (`ci.yml` `e2e`, `ai-uat.yml`) runs on bare `ubuntu-latest` via
  `playwright install --with-deps` — **not** a pinned container — while dev happens in a
  Codespace. The moment a screenshot baseline is added, local vs CI font rendering will diverge
  and the gate will flap. Pinning the container first makes S01/S02/S20 *land non-flaky* instead
  of being adopted and then disabled.
- **Concrete change:** run the visual/e2e jobs in `container: mcr.microsoft.com/playwright:v1.60.0-noble`
  (match the `@playwright/test` **1.60.0** pin in `package.json`); generate baselines in-container
  (`--update-snapshots`) and commit them; pass `--font-render-hinting=none`; set
  `snapshotPathTemplate: '{testDir}/__screenshots__/{platform}/{arg}{ext}'` in
  `playwright.uat.config.ts`. Keep this on a branch until S01's first snapshot exists.
- **Sources:** [OS-independent screenshot testing with Playwright + Docker (Adequatica)](https://adequatica.medium.com/operating-system-independent-screenshot-testing-with-playwright-and-docker-6e2251a9eb32);
  [Playwright visual testing: toHaveScreenshot, CI diffs & baselines (TestDino)](https://testdino.com/blog/playwright-visual-testing) (2026);
  [Playwright Docker docs](https://playwright.dev/docs/docker).
- **Recommended action: TRACK** — CI-architecture enabler for the not-yet-built visual gate;
  stand it up alongside S01's first baseline rather than ahead of it.

### S43 — Adopt Playwright's **Clock API** to freeze time for deterministic UAT and stable snapshots
- **What's new:** Playwright's **Clock API** (`page.clock.setFixedTime()` for a fixed `Date.now()`,
  or `page.clock.install()` to fully control timers/`Date`/rAF, then `fastForward`/`pauseAt`)
  pins time so date-sensitive UI renders identically every run. Best practice is to install
  **before** navigation so module-load code captures the fake clock.
- **Why it matters for bk-ai-apply:** the product is **time-dense** — `application_events`
  timelines, "Interview Scheduled" dates, ghosted-after-N-days logic, relative timestamps like
  "2 days ago." Both the autonomous Stagehand UAT (`e2e/ai-uat/`) and any future visual snapshot
  (S01) are **inherently flaky against a moving clock**: relative-time strings and date badges
  change between runs. Freezing time removes a whole class of nondeterminism the AI loop would
  otherwise mis-attribute to a real regression — directly on Theme 1's "make autonomous UAT
  reliable."
- **Concrete change:** in `e2e/ai-uat/_helpers/setup.ts`, add
  `await page.clock.install({ time: new Date('2026-06-15T12:00:00Z') })` before the first
  `page.goto`, **behind an opt-out** (e.g. `process.env.UAT_REAL_CLOCK`) so flows that genuinely
  need wall-clock time can skip it; require the fixed clock for any spec that will own a visual
  baseline. Validate on the `pipeline` and `discovery-applied` specs first.
- **Sources:** [Clock — Playwright Docs](https://playwright.dev/docs/clock);
  [Playwright Clock & time control: complete 2026 guide (qaskills.sh)](https://qaskills.sh/blog/playwright-clock-time-control-testing-guide) (2026).
- **Recommended action: TRACK** — scoped trial; confirm it doesn't disrupt live-agent timing
  before applying suite-wide.
