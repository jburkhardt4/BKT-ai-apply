### 1. Supabase Evals — open benchmark/framework for AI agents on real Supabase backends  `[Recommend: TRACK]`  *(Theme 1)*
- **What's new:** Supabase open-sourced `supabase/evals` (Apache-2.0, Jul 31 2026): a framework + published benchmark that runs coding agents (Claude Code, Codex, OpenCode) against **real** Supabase tasks — build a schema, debug a failed Edge Function, repair a broken RLS policy — and scores whether the agent can safely build, deploy, investigate, and fix a stateful backend. Also runs as an internal daily regression suite.
- **Why it matters for bk-ai-apply:** This is exactly the app's substrate — RLS-always-on, Edge Function scrapers, `application_events` event sourcing. Two concrete uses: (a) **evidence for ADR-010 / model-routing** — which model+config is most reliable on *Supabase* tasks, not generic coding; (b) a **pattern for an internal RLS/Edge-Function regression harness** that complements the pgTAP line (S41/S100) and the AI-UAT suite.
- **Concrete change (narrow):** Spike only. Clone `supabase/evals`, run the published suite against the repo's model roster in a scratch branch; capture results in `docs/retro/` or a new `docs/qa/agent-evals.md`. No app-code change. ADR before wiring anything into CI.
- **Source(s):** [Introducing Supabase Evals — supabase.com](https://supabase.com/blog/introducing-supabase-evals) (Jul 31 2026); [MarkTechPost](https://www.marktechpost.com/2026/08/01/supabase-releases-evals-an-open-source-benchmark-that-scores-claude-code-codex-and-opencode-on-real-supabase-tasks/) (Aug 1 2026).

### 3. Supabase Postgres Changes — AND filters, more operators, column selection  `[Recommend: TRACK]`  *(Theme 1-adjacent / data layer)*
- **What's new:** Realtime Postgres Changes now supports **AND-chained filters**, additional filter operators, and **column selection** on subscription payloads (available now, Aug 2026). Filters reject events server-side (one fewer message per subscriber); `select` trims payload bytes; the primary key always comes through. Column selection is opt-in — existing subscriptions keep receiving full rows until you add `select`.
- **Why it matters for bk-ai-apply:** The pipeline board subscribes to Realtime on `applications` / `application_events` (Realtime confirmed in 2 `src/` files). Server-side AND filters + column narrowing cut payload size and client-side filtering on the board — a clean perf win that preserves user-scoping/RLS.
- **Concrete change (narrow):** In `src/features/applications/` Realtime subscription: add `.select(...)` for only the columns the board renders and combine `user_id` + stage filters with AND. Verify RLS still gates rows; no schema/migration change.
- **Source(s):** [Postgres Changes gets AND filters, new operators, and column selection — supabase.com](https://supabase.com/blog/postgres-changes-filters-and-column-selection) (Aug 2026).
