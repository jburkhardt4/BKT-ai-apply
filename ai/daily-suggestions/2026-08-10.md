## New suggestion card

### 1. S130 — Adopt Anthropic's long-running-agent harness pattern as the skeleton for `/loop` (initializer + coding agent · `feature_list.json` · progress file · `init.sh` · end-to-end self-verification) — **[Recommend: TRACK]**
- **What's new (to this ledger):** Anthropic's engineering post **"Effective harnesses for long-running agents"** documents the exact harness they use to let a Claude Agent SDK agent build a production web app across *many* context windows. Two roles: an **initializer agent** (first session only) that scaffolds the environment, and a **coding agent** (every later session) that makes **one feature's** worth of incremental progress and leaves a clean state. Key artifacts: (a) a **`feature_list.json`** of ~200 end-to-end features each with `"passes": false`, edited *only* by flipping the `passes` field ("It is unacceptable to remove or edit tests"); (b) a **`claude-progress.txt`** progress log; (c) an **`init.sh`** that boots the dev server; (d) **git commit discipline** so bad states can be reverted; (e) mandatory **browser-automation end-to-end self-verification** (they used the Puppeteer MCP) before marking any feature `passes: true`. Each session opens with a fixed "get your bearings" preamble: `pwd` → read progress + feature list → read git log → run `init.sh` → smoke-test → then pick the highest-priority unfinished feature. A companion [`autonomous-coding` quickstart](https://github.com/anthropics/claude-quickstarts/tree/main/autonomous-coding) ships the reference code.
- **Why it matters for bk-ai-apply:** This is the missing *skeleton* for **S06**. Prior Theme-2 cards covered orchestration primitives piecemeal — Dynamic Workflows (S07), parallel fan-out + checkpoint/rewind (S22), compaction/memory discipline (S27), `/goal` completion (S55), `/fork`/`/subtask` (S77). S130 is the **end-to-end harness that ties them together**, and it maps almost 1:1 onto this repo's non-negotiables: the `feature_list.json` "flip-only, never delete a test" rule mirrors the **event-sourcing / "validate before done"** discipline; the mandatory browser self-verification is exactly the **autonomous UAT** line (Theme 1); and the "leave a clean, mergeable state each session" rule is the safety posture the unattended `/loop` floor-bump cards (S128 etc.) are protecting. The two documented failure modes — one-shotting the whole app, and a later session declaring victory prematurely — are the precise risks an unattended `/loop` on this pipeline app would hit.
- **Concrete change (narrow, when S06 is authored — no repo write today):**
  - When `.claude/commands/loop.md` is created, structure it as **initializer-vs-iteration** using a *different first-run prompt* (per the [Claude 4 multi-context-window best practices](https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/claude-4-best-practices#multi-context-window-workflows)).
  - Adopt a repo-native progress artifact — e.g. `ai/loop/progress.md` + a `ai/loop/feature_list.json` gated to flip-only edits — and wire the coding-agent preamble to `pnpm validate` + the Playwright AI-UAT smoke run (the repo's equivalent of their `init.sh` + Puppeteer check).
  - Keep it a **design note folded into the S06 spec** for now; nothing to implement without the GitHub connector.
- **Source(s):** [Anthropic Engineering — "Effective harnesses for long-running agents"](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Nov 26 2025) · [claude-quickstarts/autonomous-coding](https://github.com/anthropics/claude-quickstarts/tree/main/autonomous-coding) · [Claude 4 prompting guide — multi-context-window workflows](https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/claude-4-best-practices#multi-context-window-workflows).
