## Suggestion Cards

### 1. Stagehand 3.4 `ignoreSelectors` — strip app chrome from AI-UAT `extract()`/`observe()`  [S102]
**[Recommend: TRACK]**  ·  Theme 1 (autonomous UAT) · additive to **S05**/**S95** (the v2→v3 upgrade)

- **What's new:** Stagehand 3.4.0 (May 13 2026) adds an `ignoreSelectors` option to `extract()` and
  `observe()` that keeps noisy DOM (ads, nav, modals, toasts) out of the model's context. Same release
  defaults agent mode to `hybrid` and adds `anthropic/claude-haiku-4-5` as a CUA model.
- **Why it matters for bk-ai-apply:** the `e2e/ai-uat/` agent drives a Radix + Sonner UI. Overlays
  (`[role="dialog"]`, the Sonner toaster, sidebar/nav) inflate token count and cause the agent to act on the
  wrong element — the two biggest sources of AI-UAT flakiness and cost. `ignoreSelectors` removes them at the
  source; a cheap `claude-haiku-4-5` CUA fits ADR-010 model-routing for low-stakes steps.
- **Concrete change (do it with the S05/S95 v3 upgrade, not before):** in the AI-UAT helper that wraps
  Stagehand, pass a shared `ignoreSelectors: ['[data-sonner-toaster]', '[role="dialog"]',
  '[data-radix-popper-content-wrapper]', 'nav', 'aside']` to `extract()`/`observe()`; add a smoke assertion
  that a pipeline-stage extraction ignores an open toast. Target Stagehand ≥ 3.4 (latest 3.7.2).
- **Source:** Browserbase Changelog, "Reduce context bloat in Stagehand 3.4," **May 13 2026**.
- **Recommended action:** **TRACK** — rides on the open S05/S95 upgrade; no standalone install.

### 2. Claude Code `sandbox.credentials` — block secret reads in the unattended `/loop` sandbox  [S103]
**[Recommend: TRACK]** (IMPLEMENT-ready on approval)  ·  Theme 2 · security · additive to **S44**/**S89**/**S98**

- **What's new:** Claude Code **2.1.187** (Jun 23 2026) added the `sandbox.credentials` setting — it blocks
  sandboxed commands from reading credential files and secret environment variables.
- **Why it matters for bk-ai-apply:** the unattended `/loop` runs Bash in-sandbox with `ANTHROPIC_KEY`,
  `VITE_SUPABASE_*`, `BROWSERBASE_API_KEY`, and `TEST_USER_*` reachable in the environment. `sandbox.credentials`
  denies a subagent (or hostile content it ingests) the ability to read `.env`/`~/.aws`/secret env — directly
  serving Non-Negotiable #1-adjacent (secrets) and the S65 unattended-loop threat model. Distinct from S89
  (`filesystem.disabled`, blocks writes) and S98 (`network.strictAllowlist`, blocks egress); this closes the
  *read* path.
- **Concrete change:** add `"sandbox": { "credentials": true }` to the checked-in `.claude/settings.json`
  (the S14 settings file — still open). Verify by running a `/loop` step that greps for a known secret and
  confirming it is denied.
- **Source:** Claude Code Changelog, **v2.1.187, Jun 23 2026**.
- **Recommended action:** **TRACK** now (touches security config → wants explicit approval + the S14 settings
  file to exist). Flag as **IMPLEMENT-ready** the moment both are in place.

**[Recommend: TRACK]** (IMPLEMENT-ready on approval)  ·  Theme 2 · release safety · operationalizes **S89**/**S92**/**S96**

- **What's new:** Claude Code **2.1.163** (Jun 4 2026) added `requiredMinimumVersion` and
  `requiredMaximumVersion` managed settings — Claude Code refuses to start if its version is outside the
  allowed range.
- **Why it matters for bk-ai-apply:** the routine has repeatedly set an advisory "CLI floor" (≥ 2.1.218 at
  S92, ≥ 2.1.219 at S96) for the security/sandbox fixes the unattended `/loop` depends on — but nothing
  *enforces* it. A stale local/CI CLI can silently run the loop **without** those fixes. `requiredMinimumVersion`
  turns the advisory into a hard gate.
- **Concrete change:** set `"requiredMinimumVersion": "2.1.219"` in managed settings (repo `.claude/settings.json`
  or the org-managed policy file). Bump it in lockstep whenever a future card raises the floor. Verify by
  launching an older CC build and confirming it refuses to start.
- **Source:** Claude Code Changelog, **v2.1.163, Jun 4 2026**.
- **Recommended action:** **TRACK** now (managed-settings/policy change → wants approval; depends on S14).
